# WF-2 completion-language adjudication

The prior statement that the builder did not confuse intermediate files with delivered output was too broad. `builder-final.md` first says, “A run is complete when every input is either in a review pack or has a recorded exception, and the manifest is saved.” That definition can declare completion before the review pack reaches the phone. Later sections correctly require the delivery stage to place the pack at `[PHONE_DESTINATION_TBD]`, require a human to “confirm destination receipt,” and say, “Verify completion at the selected phone destination.”

This is an internal inconsistency of moderate severity. The later, more specific delivery and verification language preserves the true destination and prevents a clear false claim that delivery occurred, so it is not a critical failure. Still, an implementation could follow the earlier run-complete rule and report success after creating intermediate review files and a manifest. The specification should distinguish **processing complete** from **workflow delivered**: processing is complete when every input has a pack or exception plus manifest status; workflow delivery is complete only after the review set is present and verified at the selected phone destination. The original scores remain defensible, particularly outcome 3 and verification 3, and are not changed here.
