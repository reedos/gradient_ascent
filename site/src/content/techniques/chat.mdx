Chat is level 1: one request, one response, and nothing in between decides anything. You, or the
product you are using, send a question in a message, and the model returns an answer once. There
is no search step, no tool call, and no second look at its own answer: whatever comes back on
the first attempt is what you get. This is also what most people mean by "using AI": typing into
a chat app and reading back a reply.

Because there is only one step, the whole outcome depends on what happens inside that one call:
how the model was trained, and what you put in the request. Later levels add retrieval, tools and
loops around the model to make up for what one call alone gets wrong. Before any of that, it
helps to be precise about what "the model" even refers to, because a chat app, the company behind
it, and the model actually answering you are three different things often sharing one name.

This page is marked draft, not published: chat has no recorded trace and no scored result file
yet, so nothing below is measured. It is illustrated.

<Lane name="use" title="Use it">

Four kinds of name get used almost interchangeably in conversation, and keeping them apart is the
fastest way to make sense of anything on this site, or in the news about AI.

A **developer** trains models. Anthropic and OpenAI are developers. A developer's name rarely
appears on your screen by itself; it appears on everything else.

A **model** is a trained system with a specific, versioned name. Claude Sonnet 5 is a model
Anthropic trains; Anthropic's own documentation states it as released June 30, 2026, with the
model id `claude-sonnet-5`<Cite n={1}/>. The version matters because a model is frozen once
trained: Claude Sonnet 5 does not quietly get smarter next month; a new model with a new name
replaces it instead.

A **product** is something a person uses: a chat app, here. Claude, Anthropic's own product, is
described as "a helpful, intuitive, and powerful collaborator you can put to work on real
tasks"<Cite n={2}/>; behind that description, it calls one of Anthropic's models to generate each
reply. ChatGPT is OpenAI's equivalent product. A product's name and a model's name are not
interchangeable: "Claude" is not itself a model, and asking "which Claude" is really asking which
model answered you, which the product usually shows in a menu.

A **tool** is something a developer builds with, not something a person chats in directly. The
OpenAI API ships "guides and conceptual documentation for building with the OpenAI API"<Cite n={3}/>:
code calls it; a person does not type into it directly. Ollama is a different kind of tool: it
runs a model on your own machine instead of over the network, so that "nothing you run locally
ever leaves your machine"<Cite n={4}/>. Neither is a product on its own; each is what someone
else's product, or your own code, gets built on top of.

Once these four are apart, a lot of confusion resolves itself. "Is Claude as good as GPT-6 Astra"
compares a product to a model, which is not quite the right question, since a product can run
more than one model and a menu decides which. "I built this with the OpenAI API" is a tool
credit, not a product endorsement. Reading a name anywhere on this site, ask which of the four it
is; the "Out there" list at the bottom of every page groups its names the same way.

</Lane>
<Lane name="build" title="Build it">

The Build it example is level 1's entire trick: send the question, change nothing else, and see
what the model does with no documents and no tools available to it. `examples/one_call` asks
about Halvorsen, a fictional appliance maker invented for this site's synthetic documents,
specifically so a model has never legitimately seen its manuals. A correct run at this level
mostly means declining questions it cannot know the answer to, rather than inventing a
plausible-sounding number: which is exactly the failure this level exists to measure, and
exactly what <Link href="/techniques/rag/">RAG</Link> exists to fix.

The system prompt is the only lever available here, and it says so directly: answer plainly, and
say so plainly when a specific fact is not known instead of guessing at it. There is no chunking,
no search and no schema: one system message, one user message, one call.

Two things are worth noticing in the trace. First, calling the model is not itself a model
decision: the code decided to make this call, in this order, before the model said anything: the
`"model"` kind on that step and the `"code"` `decided_by` on the same step answer two different
questions (see `docs/EVALS.md`). Second, there is nothing left to decide once the call returns;
the code does not parse the answer, check it against anything, or call the model again. It hands
back exactly what came back. Run it yourself:

A newcomer building their first real thing on top of a model almost always starts here, whether or
not they call it "level 1": one prompt, sent through whichever tool wraps the developer's model,
usually that developer's own API, or a tool like Ollama that can swap which model answers without
changing the calling code.

<WhenNot>

Try <Link href="/techniques/order-zero/">level 0, no model at all</Link> first if the question has a fixed
vocabulary and repeats often enough that a keyword search or a rule can answer it with no model at
all. Level 0 is fast, free and completely predictable: three things a chat reply cannot
promise.

</WhenNot>

## How to eval it

<HowToEval questionCount={60} kinds={['lookup', 'multi-hop', 'numeric', 'unanswerable', 'conflicting sources']}>

Chat is scored on the same 60-question set as every other level (`docs/EVALS.md`). With no
documents attached, its lookup and numeric scores should sit close to level 0's floor: whatever
it gets right, it gets right from training data alone, which for a fictional appliance maker like
Halvorsen should be close to nothing. The one place a single call can beat a keyword score is
unanswerable questions, if the system prompt's instruction to decline rather than guess actually
holds: it can say "I don't know" in its own words instead of returning an irrelevant passage.

No result file exists yet for any level (see `docs/EVALS.md`). Run
`python scripts/eval_run.py --example one_call --model stub --dry` to project the token cost of a
run before spending anything on a real one.

</HowToEval>
